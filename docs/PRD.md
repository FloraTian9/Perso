# Perso · 产品需求文档 PRD

> MBTI 人格圆桌对话生成器
> 核心体验：太真实了、太好笑了、要发给某个人

---

## 一、产品定位

### 是什么
用户输入一个日常话题，不同 MBTI 人格围坐圆桌展开对话。对话足够准、足够好笑，让用户认出身边的某个人，忍不住截图发出去。

### 不是什么
- 不是决策工具（不帮用户解决问题）
- 不是 MBTI 测试（不给用户贴标签）
- 不是严肃的心理分析

### 目标用户
熟悉 MBTI 的年轻用户（18-28岁），知道自己和身边人的人格类型，看到准确的人格描写会有强烈的共鸣和分享欲。

### 核心价值
**社交货币**——用完之后想发给某个人说「这就是你」或「这就是我们」

---

## 二、核心功能

### 2.1 两种模式

**旁观模式**
- 用户选择话题 + 选择参与的人格组合
- AI 自动生成一段人格圆桌对话
- 用户观看、截图、分享
- 作为产品入口，让用户先感受对话质量

**参与模式**（核心）
- 用户进入圆桌（用户以自己身份参与，不扮演任何人格）
- 其他人格由 AI 扮演
- AI 控制的其他人格实时回应
- 对话有来有往，用户是参与者而非旁观者


### 2.2 功能优先级

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 旁观模式生成对话 | P0 | v1 必须有 |
| 参与模式 | P0 | v1 必须有，核心体验 |
| 话题选择（预设） | P0 | v1 必须有 |
| 话题自由输入 | P0 | v1 必须有 |
| 人格选择（16个全做） | P0 | v1 必须有 |
| 旁观模式播放控制（暂停/回退/进度条） | P0 | v1 必须有 |
| 系统自动配置对立人格组合 | P0 | v1 必须有 |
| 分享卡片 | P0 | v1 必须有，对话结束后生成可保存图片 |
| 话题库（更多话题） | P1 | 持续迭代 |
| 语音 TTS | P2 | v2 做 |
| 分享视频 | P2 | v2 做 |
| 对话历史保存 | P2 | v2 做 |
| 用户账号系统 | P3 | v3 做 |

## 三、用户流程

### 公共流程
```
进入首页
  ↓
选择话题（预设 or 自由输入）
  ↓
选择参与人格（2-4个）
  - 默认：系统自动配置冲突张力最大的组合
  - 可选：用户手动调整
  ↓
选择模式
  [旁观这场对话]（默认）    [加入对话]
  ↓
进入对应模式
```

### 旁观模式
```
进入圆桌页面
  ↓
对话流式逐条生成（像直播）
  - 生成中：左下角显示时间戳（00:12...），实时推进
  - 用户可以回滚查看已生成的消息，但不能跳到未生成的部分
  - 暂停按钮：暂停生成，自由浏览
  - 继续按钮：从暂停处接着生成
  - 结束按钮：手动终止对话
  ↓
对话自动生成到自然结尾（约10-15条）或用户手动终止
  ↓
生成完毕：时间戳变成完整进度条，可拖动到任意位置回看
```

### 参与模式
```
进入圆桌（用户以自己身份参与，不扮演任何人格）
  ↓
AI 人格先开场发言（1-2条）
  ↓
用户直接发言（以「我」的身份）→ 1-2个 AI 人格回应
  ↓
AI 人格之间也会互相回应，不只回应用户
  ↓
持续对话，无轮数限制，用户点结束按钮终止
```

## 四、页面设计

### 4.1 首页

**布局：**
- 顶部：产品名 Perso + 一句话介绍
- 中部：话题选择区
  - 预设话题卡片（横向滚动，分类展示）
  - 自由输入框：「输入任何话题……」
- 底部：开始按钮

**预设话题分类：**

职场
- 要不要裸辞
- 被领导当众批评怎么办
- 同事抢功劳怎么处理

关系
- 要不要跟他/她表白
- 异地恋值不值得坚持
- 朋友借钱不还要不要开口

日常
- 今晚吃什么
- 要不要买这个贵的东西
- 要不要早睡

人生
- 要不要考研
- 要不要回老家
- 30岁了还在迷茫正常吗

### 4.2 人格选择页

**选择逻辑（两种模式通用）：**
- 展示16个人格，每个人格有简短的一句话特征
- 用户选 2-4 个人格
- 默认：系统自动配置冲突张力最大的组合
- 可选：用户手动调整
- 选完后显示「这个组合的冲突预告」（一句话，制造期待）

**参与模式的补充说明：**
- 用户以自己身份加入圆桌，不扮演任何人格
- 选的 2-4 个人格是对话中的 AI 角色，用户作为"真人"与它们对话

### 4.3 圆桌页（核心页面）

**视觉风格：黑客终端风**
- 深色背景（纯黑 #0a0a0a）
- 人格头像围坐圆桌
- 对话以文字气泡形式出现
- 终端字体（JetBrains Mono）
- 说话时头像有脉冲动画

**布局：**
- 上方：圆桌视图，人格头像围坐
  - 每个头像显示人格类型代码（INTJ、ENFP…）
  - 说话时头像高亮 + 波形动画
- 中间：对话气泡流（滚动）
  - 每条发言显示人格标签
  - 发言类型标签（反驳、追问、打断…）
- 下方（参与模式）：用户输入框
  - 显示「你：」
  - 发送按钮

**圆桌人格布局：**
- 2个人格：左右对坐
- 3个人格：三角形
- 4个人格：四角分布
- 用户（参与模式）：固定在底部中间

### 4.4 分享页

对话结束后可生成分享卡片：
- 话题标题
- 最精彩的3-5条对话
- Perso 品牌标识
- 适合截图发小红书/朋友圈

## 五、对话设计原则

### 5.1 对话质量标准
- ✅ 每个人格说话有强烈辨识度，不看名字也能猜出是谁
- ✅ 对话有真实的来回，不是每人说一段独白
- ✅ 有打断、追问、反驳
- ✅ 偶尔有意外的共识，增加真实感
- ❌ 不说「作为 INTJ 我认为……」（太刻意）
- ❌ 不给建议清单
- ❌ 不过于礼貌，失去真实感

### 5.2 参与模式交互原则
- 用户发言后，1-2个人格立即回应（不是全部同时说）
- 其他人格之间也会互相回应，不只回应用户
- 用户的发言会真实影响对话走向
- 每轮 AI 回应控制在2-4句，不写长段

### 5.3 话题处理
- 任何日常话题都可以进入
- 对于敏感话题（政治、宗教等）温和拒绝，引导换话题
- 话题越具体越好：「要不要裸辞」比「聊聊工作」好

## 六、技术要求

### 6.1 技术栈
- 前端：Next.js（React）+ Tailwind CSS（**Mobile First**，桌面端适配）
- API：Qwen API（默认 `qwen3.5-plus-2026-02-15`，兼容 OpenAI 格式；可通过 `QWEN_MODEL` 切换）
- 后端/数据库：Supabase（PostgreSQL）
- 部署：Vercel

### 6.2 性能要求
- 旁观模式：对话流式生成，用户看到第一条发言 < 2秒
- 参与模式：用户发言后 AI 回应 < 3秒
- 支持流式输出（streaming），逐字显示

### 6.3 数据存储
v1 需要存储用户对话数据，用于产品迭代和质量分析。

**必须存储：**
- session_id：每场对话的唯一标识
- topic：话题内容（预设 or 自输入）
- mode：旁观 / 参与
- personas：参与的人格组合
- messages：完整对话记录（含每条消息的人格标签和时间戳）
- created_at：对话开始时间
- ended_by：自然结束 / 用户手动终止

**有了更好：**
- 用户在哪条消息停留时间最长
- 用户是否看完（中途退出率）
- 参与模式下用户发了几条消息

**隐私原则：**
- 不收集用户个人身份信息（v1 无账号系统）
- 对话数据仅用于产品迭代，不对外分享

## 七、版本规划

### v1（当前）
- 旁观模式 + 参与模式
- 预设话题 + 自由输入
- 16个人格全做
- 圆桌界面（Mobile First，黑客风）
- 旁观模式播放控制（暂停/回退/完成后进度条）
- 分享卡片（对话结束后生成可保存的图片卡片，发小红书/朋友圈）
- 数据存储（Supabase）

### v2（验证后）
- 语音 TTS（每个人格不同声线）
- 分享视频（一键生成对话视频）
- 对话历史保存
- 更丰富的话题库

### v3（增长期）
- 用户账号系统
- 多语言
- 移动端 App

---

## 八、成功指标

v1 上线后，用小红书的用户反应来验证：
- 有没有人说「太准了」「太真实了」
- 有没有人 @ 朋友说「这就是你」
- 笔记有没有被收藏和转发

这些反应出现了，说明核心体验成立，再决定 v2 往哪个方向深化。
